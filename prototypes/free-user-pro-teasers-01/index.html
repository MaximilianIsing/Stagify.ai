Showing free users the Pro toolbar — 8 directions

The request: “Right now, the only display where free users are shown pro options is in the staging drop down where you can see the locked ones. But I would like you to use the prototype scale to draft up different ways that we can show free users all the pro features in the main staging, except locked behind certain lock icons, or stuff like that.”

All eight assume a hard lock: nothing here spends a render. Every locked control routes to Stagify+ ($11.99/mo, 7-day trial). Locked rows are links, never aria-disabled — the same rule the nav dropdown already follows. Aggressiveness deliberately spans from variant 1 (whisper) to variant 8 (shout).

1Ghost Panel

The truest “show them what they’re missing”: the Pro panel that already exists in the DOM simply stops being hidden for free accounts and renders desaturated and inert, with one unlock line beneath it. Pick this if you want the change shipped this week — it is a class swap plus ~30 lines of CSS, it touches no layout the paying user sees, and the shape of the panel is literally the shape they’d get. The risk is that grey-on-grey reads as “broken” rather than “locked” to a first-time user who has no memory of the panel ever being live.

+ Cheapest possible ship + Shows exact real UI + No new copy to translate − Greyed can read as broken − Easy to scroll past

2Lock Gutter

Rather than invent a new locked-state language, this borrows the one the product already ships: the nav dropdown’s 30px left gutter with a 13px padlock, slate label text, row is a working link. Every row in the toolbar — free and Pro alike — gets the gutter, so labels stay aligned and the padlock is the only difference. Pick this if consistency matters more than drama: a user who has seen the Staging dropdown already knows exactly what a padlock in that gutter means. The cost is that Pro features get compressed into one-line rows, so “Furniture reference photos” never gets to explain itself.

+ Reuses a shipped idiom + Reads as inventory, not ad + Every Pro feature fits, incl. the studios − One line each = no explanation − Lowest urgency of the eight

3Teaser Rail

The upsell is quarantined into a single collapsed strip below the Process button, so the free configure-and-render path is byte-for-byte what it is today and nobody has to walk past a paywall to stage a photo. Expanded, it has room to actually sell — a thumb, a name and a sentence per feature, all eight of them, plus the price. Pick this if you are worried about annoying the free tier or about the toolbar getting long on a phone. The tradeoff is honest: below the primary CTA is the lowest-attention real estate in the modal, and most users will never open it.

+ Zero disruption to free flow + Room to explain each feature + Collapsed by default = tiny footprint − Below the CTA, so low attention − Needs 6–8 thumbnail assets
Media 6 thumbs, ~40KB webp JS ~15 lines toggle Mobile grid → 1 col I18N ~14 strings Collapsed +44px · open +330px

4Locked on Interact

The Pro controls render fully live — no grey, no padlock at rest, just a small “Stagify+” pill. The wall only materialises the moment someone reaches for one, unfolding an upgrade sheet inside that exact row and naming the thing they just tried to do. Pick this because it converts on demonstrated intent rather than on exposure: the person who dragged the Generations slider to 3 has told you what they want, and you can answer them in those words. The honest downside is that it’s a bait-and-switch by construction, and doing it on every control every session is how you earn a “this app is nagware” review. Try the slider or the model dropdown below.

+ Fires on real intent + Copy adapts to the control touched + Invisible until provoked − Feels like a bait-and-switch − Needs per-session frequency capping

5Pro Shelf

A permanent tab welded to the right edge of the modal pulls out a full-height drawer holding every Pro feature at once — the four toolbar controls plus the three studios and the gallery limits, which no inline treatment has room for. Pick this if you want one canonical upsell surface you can iterate on without ever touching the staging toolbar again, and if you want free users to be able to browse the whole Pro product without leaving their photo behind. The catch: a drawer is an opt-in, so its ceiling is set by how many people notice a vertical tab, and on a 390px screen it eats the entire modal.

+ Toolbar stays untouched + Only place all 8 features fit + One surface to A/B forever − Opt-in ceiling; tab is easy to miss − Covers the whole modal on phones
Media optional hero, none required JS ~40 lines + focus trap Mobile full-width overlay A11Y needs Esc + focus return Toolbar height +0px

6Earned Moment

Nothing changes in the toolbar at all. The pitch waits until a free render has actually landed and then appears under the result, offering precisely the things that would have improved that photo — “this took the fast model”, “you got 1 of a possible 3”, “that sofa is still in the frame.” Pick this if you believe the free tier’s job is to prove the product works and the upsell’s job is to arrive one second after it does. It reuses the overlay pattern already built for the daily-limit notice. The cost is reach: it only ever speaks to people who finished a render, which is a fraction of the people who open the modal.

+ Fires at peak proven value + Free workflow 100% untouched + Reuses the limit-overlay pattern − Only reaches completed renders − Competes with the download button

7Reveal Toggle

One switch at the top of the toolbar: Show Stagify+ options. Off, the free user sees exactly today’s four controls. On, the toolbar morphs into the full Pro toolbar — gradient border, every control present and padlocked — so they can look at the real thing and turn it back off. Pick this if you want maximum exposure with consent: nobody is shown a paywall they didn’t ask for, but the ask is one tap away and sits above the fold rather than below the CTA. Remembering the state per user is what makes or breaks it; forget that and it’s a toggle people flip once.

+ Consent-based, can’t feel nagging + Shows the genuine Pro layout + Sits above the fold − Extra tap before any pitch lands − Needs persisted per-user state
Media none JS ~25 lines + localStorage Mobile pair grid → 1 col A11Y role=switch, aria-checked Off +46px · on +250px

8Live Receipt the swing

The unconventional one. A permanent navy panel beside the toolbar reads back, in real time, what the user is about to get versus what the same settings would produce on Stagify+ — and it updates as they change room type, style, or anything else. It reframes the paywall from a feature list into a diff of this specific render, which is a much harder thing to scroll past than a marketing block. Pick this if conversion is the priority and you can accept that it is the loudest option here: the panel is always on screen, it never stops selling, and on a phone it has to become a strip under the CTA, which is where variant 3 already lives. Change the pickers below and watch it rewrite.

+ Personalised to the current render + Impossible to miss + Concrete diff beats a feature list − Loudest; risks nagware perception − Needs a whole second layout on mobile
