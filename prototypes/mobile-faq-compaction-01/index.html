Mobile FAQ compaction

Request: the nine homepage FAQ cards run roughly 800px of phone scroll. Keep the same nine questions, same count, all in the DOM, but stop charging that much vertical space to visitors who do not care about the FAQ.

Eight directions, from a tighter list to removing the section from the flow entirely.

22 September 2026

Ranking

Scored on fit to the brief 30, distinctiveness 20, build cost 20, mobile and accessibility 15, first-glance pull 15.

  1. 02Four Plus More 90%A-

    Biggest space win per line of code, and nothing leaves the page.

  2. 01Hairline List 82%B-

    Pure CSS, zero risk, keeps all nine scannable. Half the win.

  3. 03Topic Chips 81%B-

    Solves space perfectly and kills every FAQ impression to do it.

Hairline List

B- 82%

One glass sheet, nine hairline rows. No new markup, no new strings, no JavaScript.

Roughly 430px collapsedCSS only

Frequently asked questions

How it works

  • One mobile media query in home.css, below the 1001px plan gate.
  • Card shells collapse into a single sheet with dividers between rows.
  • Question drops to 14.5px so most fit one line at 360px.
  • Ships in one sitting, no markup or language packs touched
  • All nine questions stay visible, scan time unchanged
  • Nothing to break if a stylesheet loses its race
  • Keyboard and screen reader behaviour identical to today
  • Still 430px of scroll for uninterested visitors
  • Long questions wrap and a denser row makes wraps uglier
  • Loses the glass card look the rest of the page uses
  • Smallest visual change, so it reads as a tweak

Roughly 240px collapsedOne new string

Frequently asked questions

How it works

  • Rows five to nine hide under a mobile-only rule, never removed from the DOM.
  • The toggle flips one class, so the FAQPage schema and deep links keep working.
  • A deep link such as #faq-privacy expands the rest before scrolling.
  • Needs one label across the eleven language packs.
  • Largest space saving without hiding the section itself
  • Four visible questions still advertise what the FAQ answers
  • Roughly ten lines of JavaScript, rest is CSS
  • Crawlers and deep links see all nine unchanged
  • Adds a translated string to eleven language packs
  • Five questions cost an extra tap to discover
  • Choosing which four show is an editorial call
  • Toggle needs aria-expanded and focus handling done properly

Topic Chips

B- 81%

The nine room labels become a chip grid. Tap a topic, its question and answer appear below.

Roughly 200px with one openNo new strings

Frequently asked questions

How it works

  • Reuses faq.rooms.*.label, already translated and currently hidden below 1001px.
  • The chip row is the mobile echo of the desktop floor plan idea.
  • Panel height changes as answers differ, so the section jumps a little.
  • Smallest footprint that still shows all nine entries
  • Every label already exists in all eleven languages
  • Carries the plan metaphor down to phone width
  • Visitors scan topics, not questions, so intent matching gets harder
  • Long labels in German and French wrap the chip row
  • Needs real tab semantics to stay accessible
  • Panel resizing on each tap moves the page under the thumb

One Door

D 64%

The entire section behind a single disclosure with a count. Cheapest possible answer to the brief.

Roughly 56px collapsedMarkup only
Frequently asked questions 9

How it works

  • One outer details element wrapping the list, mobile only.
  • Nothing inside changes, so plan mode above 1001px is untouched.
  • The count chip is the only hint of what is inside.
  • Removes essentially all of the space, immediately
  • No JavaScript and no new copy to translate
