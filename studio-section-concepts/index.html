Frame + style rail, hold to peek

Closest silhouette to today, new axis. One big frame, style chips underneath, and the before/after proof survives as a press-and-hold instead of a drag handle — hold the frame (or the button) and the staging drops away to the empty room. One control, no drag math, no touch-action tuning. The dashed Custom chip is the eighth option: your own prompt.

  • Keeps the empty-room proof without a second slider
  • Least disruptive of the style-axis three
  • Hold beats drag on touch — nothing to fight the scroll
  • Hold-to-peek is undiscoverable without a label
  • One look at a time — the variety is told, not shown

4

Shuffle deck — “stage it again”

Sells the behaviour rather than the output: the staged photos are a stack of cards, and the button flicks the top one away to reveal a different take on the same room. Note the copy is careful — the product has no shuffle button; you re-run, and because nothing pins a seed on the main staging path the result genuinely differs. Saying “shuffle” here would promise a control that doesn’t exist.

  • Only concept that shows re-staging as a motion
  • One interaction, impossible to misunderstand
  • Implies a re-roll button the product doesn’t have
  • Multiple options per run is Stagify+ only, max 3
  • Hides seven of eight images behind a click

Listing reel — a whole home, not one hero shot

Widens from one photo to one listing. Six frames scroll horizontally and flip empty → staged in a stagger as the row enters view, with a global Before/After toggle. This is the only concept that sells the workflow — the thing an agent actually does — rather than a single transformation. It also reuses four real pairs you already ship (three interiors plus the exterior).

  • Reuses 4 real pairs already in the repo
  • Matches how the product is really used
  • Horizontal scroll costs no vertical space
  • Heaviest media payload of the set
  • Off-screen frames are easy to miss entirely

Live stage — the clock

Auto-plays the pipeline: a scan sweeps the empty room, the staged version fades in, and a step rail tracks upload → read → stage → done. Read the caveat before picking this one: “about 8 seconds” appears eight times on the home page but exists nowhere in the code — no constant, no measured p50. The only real timing figure in the repo is a 180-second client abort. A running clock turns unsourced marketing prose into a measured-looking claim.

  • Speed is the real advantage over traditional staging
  • Shows the product working, not just its output
  • Dramatises a number that isn’t measured anywhere
  • #compare already owns the speed argument
  • Autoplay + IO is the most fragile thing here

Wipe, evolved — the conservative option

Keeps the drag, changes what it means. The three room buttons become style buttons, so dragging always compares the same empty room against the style you picked — and the styles get named. Reuses mountWipe() untouched, which also keeps it alive for #exterior-studio-demo in the showcase carousel. Cheapest ship on this page by a wide margin.

  • Reuses the existing widget and its accessibility work
  • Names the styles at almost no cost
  • Only 7 new renders, no new interaction to test
  • Still the third drag slider on the page
  • Doesn’t fix the “feels generic” complaint
